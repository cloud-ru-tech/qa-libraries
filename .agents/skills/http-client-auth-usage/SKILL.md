# IAM authorization for HTTP clients

`http_client_auth` provides an `httpx.Auth` implementation that puts an IAM-issued access token into every outgoing request and keeps that token fresh. Nothing else — no client, no transport, no retry policy.

You always assemble two objects:

1. **An IAM client** — decides *which* IAM endpoint issues the token: `IAM_HttpClient` / `IAM_OpenID_HttpClient` and their async twins. These are `http_client` subclasses, so every `options.with_*` applies to them.
2. **An auth object** — `IAM_Auth` or `IAM_AsyncAuth`. Takes the key pair and the IAM client, and is passed to whatever sends the requests.

The auth object is a plain `httpx.Auth`, so it works with `httpx.Client`, `httpx.AsyncClient`, and any `http_client` client via `options.with_auth(...)`.

## Hard rules

1. **Sync auth goes to a sync client, async auth to an async client.** Mixing them does not raise — requests just go out with no `Authorization` header at all. See `references/pitfalls.md`; this is the single most expensive mistake with this library.
2. The auth object does **not** own the IAM client. Close the IAM client yourself, ideally with a context manager.
3. Never build the `Authorization` header by hand next to this auth. It sets the header itself on every request, including the retry.
4. Never write your own token cache, expiry check, or refresh-on-401 loop around it. That is exactly what the library already does, under a lock.
5. When you attach a logger to the IAM client, pass `IAM_SANITIZE_KEYS` — the `http_client` default mask list does not cover `client_secret` and `id_token`.
6. Do not read or write the token store directly from application code to "warm it up". Getting and issuing the token is serialized under the auth object's lock; a side write is not.

## Canonical setup (sync)

```python
from http_client import HttpClient, options
from http_client_auth import IAM_Auth, IAM_HttpClient

with IAM_HttpClient("https://iam.example.com") as iam_client:
    auth = IAM_Auth("your_key_id", "your_key_secret", iam_client)

    with HttpClient("https://api.example.com", options.with_auth(auth)) as client:
        response = client.get("/orders")
```

With bare `httpx` the auth object is passed the same way:

```python
import httpx

response = httpx.get("https://api.example.com/orders", auth=auth)
```

## Canonical setup (async)

Same shape, async classes on both sides:

```python
from http_client import AsyncHttpClient, options
from http_client_auth import IAM_AsyncAuth, IAM_AsyncHttpClient

async with IAM_AsyncHttpClient("https://iam.example.com") as iam_client:
    auth = IAM_AsyncAuth("your_key_id", "your_key_secret", iam_client)

    async with AsyncHttpClient("https://api.example.com", options.with_auth(auth)) as client:
        response = await client.get("/orders")
```

## Choosing the IAM client

The auth classes are endpoint-agnostic — swapping the IAM client is the only change needed to move between IAM APIs.

| Client | IAM API | Route |
|---|---|---|
| `IAM_HttpClient` | public API | `POST /api/v1/auth/token` |
| `IAM_AsyncHttpClient` | public API, async | `POST /api/v1/auth/token` |
| `IAM_OpenID_HttpClient` | OpenID | `POST /auth/system/openid/token` |
| `IAM_OpenID_AsyncHttpClient` | OpenID, async | `POST /auth/system/openid/token` |

```python
from http_client_auth import IAM_Auth, IAM_OpenID_HttpClient

iam_client = IAM_OpenID_HttpClient("https://iam.example.com")
auth = IAM_Auth("your_key_id", "your_key_secret", iam_client)
```

Since these are `http_client` subclasses, configure them through constructor options like any other client — timeouts, TLS, request id, a retry decorator:

```python
iam_client = IAM_HttpClient(
    "https://iam.example.com",
    options.with_timeout(10),
    options.with_autogenerated_request_id(),
)
```

`authorize(key_id, key_secret)` is also callable directly when you need the raw `AuthData` (access token, lifetime, optional `id_token`) rather than an auth object.

## Behaviour you can rely on

- The token is issued lazily, on the first request that needs it — constructing `IAM_Auth` performs no I/O.
- A cached token is reused until it expires. Expiry is computed from IAM's `expires_in` minus a safety margin of 30 seconds, and for tokens living less than a minute the margin shrinks to half the lifetime.
- Exactly **401** triggers one refresh and one retry of the original request. 403 and every other status is passed through to the caller untouched.
- Concurrent callers sharing one auth object issue the token once, not once per caller — both the sync and the async class serialize issuing internally.

## Token stores

By default each auth object keeps tokens in memory, in itself. Two auth objects do not share a token even for the same key pair.

To share tokens across processes, implement `AuthStore` (sync) or `AsyncAuthStore` (async) and pass it as the fourth argument. Tokens are keyed by `key_id`.

```python
import json
from datetime import datetime

from http_client_auth import AuthStore, IAM_Auth, IAM_HttpClient, Token


class RedisAuthStore(AuthStore):
    def __init__(self, redis_client):
        self._redis = redis_client

    def get(self, key: str) -> Token | None:
        raw = self._redis.get(f"token_for:{key}")
        if raw is None:
            return None
        data = json.loads(raw)
        return Token(data["access_token"], datetime.fromisoformat(data["expires_at"]))

    def set(self, key: str, token: Token) -> None:
        self._redis.set(
            f"token_for:{key}",
            json.dumps(
                {
                    "access_token": token.access_token,
                    "expires_at": token.expires_at.isoformat(),
                }
            ),
        )


auth = IAM_Auth("your_key_id", "your_key_secret", iam_client, RedisAuthStore(redis_client))
```

`AsyncAuthStore` is the same interface with `async def get` / `async def set`. It exists so that a network round trip to the store does not block the event loop — never satisfy it by wrapping a blocking client.

`Token.expires_at` is a timezone-aware UTC `datetime` and already includes the safety margin. A store must round-trip it without losing the timezone; store the ISO string, not a naive timestamp.

Store implementations must not raise on a cache miss — return `None`. An exception from `get` propagates straight out of the request the caller made.

## Logging IAM traffic

The IAM request carries the secret key and the response carries a JWT. Neither key is in the `http_client` default mask list, so pass `IAM_SANITIZE_KEYS` explicitly:

```python
import logging

from http_client import options
from http_client_auth import IAM_SANITIZE_KEYS, IAM_OpenID_HttpClient

iam_client = IAM_OpenID_HttpClient(
    "https://iam.example.com",
    options.with_logger(logging.getLogger("iam"), sanitize_keys=IAM_SANITIZE_KEYS),
)
```

To add your own paths, concatenate rather than replace: `sanitize_keys=[*IAM_SANITIZE_KEYS, "meta.tenant"]`.

The business client is unaffected — `authorization` is masked by `http_client` out of the box.

## Errors

| Exception | Raised when |
|---|---|
| `IAM_Error` | base class — catch this to handle any authorization failure |
| `IAM_AuthError` | IAM answered with a non-200 status |
| `IAM_InvalidJsonResponseError` | IAM answered 200 but the body is not valid auth data |

Both are raised from inside the request the caller made, so a failure to authorize surfaces at the business call:

```python
from http_client_auth import IAM_Error

try:
    response = client.get("/orders")
except IAM_Error as e:
    logger.error("Authorization failed: %s", e)
```

`IAM_AuthError`'s message includes the IAM response body; `IAM_InvalidJsonResponseError`'s deliberately does not, because a 200 body holds a live token.

## Testing clients that use the auth

The auth makes a real HTTP call, so a test must mock **two** routes: the IAM token endpoint and the endpoint under test. With `pytest-httpx`:

```python
from http_client_auth.iam_client import PUBLIC_API_AUTHORIZE_ROUTE
from pytest_httpx import HTTPXMock


def test_sends_authorized_request(httpx_mock: HTTPXMock) -> None:
    httpx_mock.add_response(
        url=f"https://iam.example.com{PUBLIC_API_AUTHORIZE_ROUTE}",
        method="POST",
        json={"access_token": "test-token", "expires_in": 3600},
    )
    httpx_mock.add_response(url="https://api.example.com/orders", method="GET", json=[])

    with IAM_HttpClient("https://iam.example.com") as iam_client:
        auth = IAM_Auth("key", "secret", iam_client)
        with HttpClient("https://api.example.com", options.with_auth(auth)) as client:
            client.get("/orders")

    orders_request = httpx_mock.get_requests(url="https://api.example.com/orders")[0]
    assert orders_request.headers["Authorization"] == "Bearer test-token"
```

To exercise the expiry path, hand the auth a pre-filled store instead of faking the clock:

```python
store = InMemoryAuthStore()
store.set("key", Token("stale-token", datetime.now(UTC) - timedelta(seconds=1)))
```

`pytest-httpx` does not reproduce every transport behaviour — notably it reads request bodies itself, so a test built on it cannot prove that streaming bodies survive a 401 retry. Drive `sync_auth_flow` / `async_auth_flow` directly when that is what you are checking.
