# Option catalog and configuration

All options live in `http_client.options`.

## Transport and connection

### `with_timeout(timeout: TimeoutTypes) -> ClientOption`

Client timeout. Accepts a number of seconds or an `httpx.Timeout`.

The default is `httpx.Timeout(60)`, i.e. 60 seconds for each phase (`connect`, `read`, `write`, `pool`).

```python
from httpx import Timeout

options.with_timeout(Timeout(connect=5.0, read=30.0, write=5.0, pool=1.0))
```

Precedence: an explicit `timeout=` on the call wins over the client timeout. Passing `timeout=None` on a call deliberately disables the timeout for that request.

### `with_follow_redirects(max_redirects: int = 20) -> ClientOption`

Enables redirect following and sets the limit. The default comes from `httpx._config.DEFAULT_MAX_REDIRECTS`.

Without this option the client does not follow redirects. Override per request with `client.get(url, follow_redirects=True)`.

### `with_verify_context(*, verify: ssl.SSLContext | str | bool) -> ClientOption`

TLS verification context. Accepts an `SSLContext`, a path to a CA bundle (converted to an `SSLContext` internally), or `False` to disable verification. Applies to both `HttpClient` and `AsyncHttpClient`.

⚠️ `False` disables certificate checking entirely — local debugging only, never production.

### `use_truststore() -> ClientOption`

Certificate verification through the system trust store. Requires the extra dependency:

```shell
pip install "cloudru-qa-http-client[truststore]"
```

Without `truststore` installed it raises `ImportError` with a hint. Internally it calls `with_verify_context`.

## Authentication

### `with_auth(auth: AuthTypes) -> ClientOption`

Any httpx authentication mechanism: `BasicAuth`, `DigestAuth`, a callable, or your own `httpx.Auth` subclass.

```python
from httpx import BasicAuth

options.with_auth(BasicAuth("user", "password"))
options.with_auth(lambda request: request.headers.update({"Authorization": f"Bearer {token}"}))
```

Override for a single request: `client.get(url, auth=other_auth)`.
Disable authentication entirely for a request: `client.get(url, anonymous=True)` — `auth` is then not applied at all, not even one passed explicitly. Other per-call arguments such as `follow_redirects` still apply.

## Headers

### `with_default_headers(headers: dict[str, str]) -> ClientOption`

Adds a hook that fills in each header only when the request does not already carry it. A value passed per request wins over the default, matching `httpx` semantics.

### `with_autogenerated_request_id() -> ClientOption`

An `X-Request-ID` header carrying a random UUID4 per request. The hook is inserted at the **front** of the list, so the identifier is visible to later hooks, including the logging one.

### `with_autogenerated_traceparent() -> ClientOption`

A `Traceparent` header in W3C Trace Context format: `00-<32 hex>-<16 hex>-01`. Also inserted at the front of the list.

This is standalone generation, not an OpenTelemetry integration: no context is picked up from the current span.

## Event hooks

### `with_request_hook(hook: EventHook) -> ClientOption`
### `with_response_hook(hook: EventHook) -> ClientOption`

Append a hook to the corresponding list. The contract matches [httpx event hooks](https://www.python-httpx.org/advanced/event-hooks/): the hook receives a `Request` (or `Response`) and its return value is ignored. Mutate the object in place.

```python
def add_tenant(request: httpx.Request) -> None:
    request.headers["X-Tenant"] = "acme"
```

For `AsyncHttpClient`, synchronous hooks are wrapped into coroutines during `__init__`, so the same set of options works for both clients. Native async hooks are accepted too; call order is preserved regardless of mixing.

## Transport decorators

### `with_send_decorator(decorator: SendDecorator) -> ClientOption`
### `with_stream_decorator(decorator: StreamRequestDecorator) -> ClientOption`

Wrap `_send` and `_stream_request` respectively. Composition happens once, in `__init__`:

```python
for decorator in decorators:
    func = decorator(func)
```

Consequences:

- The last decorator added becomes the outermost.
- Register decorators only in constructor options; late registration raises `RuntimeError`.
- For `AsyncHttpClient` the decorator must be async — there is no auto-wrapping, unlike event hooks.

Protocol types for annotations are in `http_client.types`.

## Logging

### `with_logger(logger, *, sanitize_keys=None, json_indent=None, use_line_breaks=None, log_level=None, use_default_sanitize_keys=True) -> ClientOption`

| Parameter | Type | Meaning |
|---|---|---|
| `logger` | `logging.Logger` | where to write |
| `sanitize_keys` | `Sequence[str] \| None` | glom paths to fields replaced with `****` |
| `use_default_sanitize_keys` | `bool` | also mask the built-in secret list (default `True`) |
| `json_indent` | `int \| None` | indent used when serializing JSON parts of the record |
| `use_line_breaks` | `bool` | newlines between record parts instead of spaces |
| `log_level` | `int \| None` | record level, defaults to `INFO` |

Record format:

```
Request: id=<uuid> Method: [GET] https://host/path QueryParams: {...} Headers: {...} Body: {...}
Response: id=<uuid> Status: 200 [OK] Headers: {...} Body: {...}
```

`id` is an internal identifier linking a request to its response. It is stored in `request.extensions["trace_id"]` and has nothing to do with server-side tracing.

Bodies are rendered by `Content-Type`:

| `Content-Type` | `Body:` shows |
|---|---|
| `application/json` | the parsed, masked, re-serialized body |
| `text/plain` | the body as is |
| `application/octet-stream` | the decoded body, or `<binary content (N bytes)>` if it is not text |
| anything else | `<not logged, content-type: ...>` |
| absent (no body) | nothing — the `Body:` part is omitted |

So an omitted `Body:` means there was no body, while `<not logged, ...>` means there was one and the type is not rendered.

A parsing failure in any part never breaks the request — the log gets `<Error parse: ExceptionType>` instead. Only the exception class is recorded: its message could carry fragments of the body or URL.

### Masking

A built-in list of common secrets is masked by default — `authorization`, `proxy-authorization`, `cookie`, `set-cookie`, `x-api-key`, `api-key`, `api_key`, `access_token`, `refresh_token`, `password`, `secret`, `token` (`event_hooks.DEFAULT_SANITIZE_KEYS`). Anything in `sanitize_keys` is added on top. Turn the defaults off only with `use_default_sanitize_keys=False`.

Masking covers the access-log records this library writes — not `httpx` exceptions, which may carry the full URL including query. Do not put secrets in URLs.

`sanitize_keys` is applied to headers, query parameters, and the parsed JSON body — independently, each path is looked up in all three. A path that does not match is silently skipped.

Syntax is [glom](https://glom.readthedocs.io/en/latest/):

| Path | What it masks |
|---|---|
| `authorization` | the `Authorization` header (httpx lowercases names) |
| `user.password` | a nested object field |
| `items.*.token` | a field inside every array element |
| `*.credentials.secret` | a field when the body itself is an array of objects |

### `configure_logging(...)` — global defaults

```python
from http_client import configure_logging
from http_client.config import LoggingConfig

configure_logging(
    options=LoggingConfig(
        log_level=logging.INFO,
        json_indent=None,
        use_line_breaks=False,
        octet_stream_log_maxlength=1024,
        plain_text_log_maxlength=None,
        json_log_maxlength=None,
    )
)
```

Pass a `LoggingConfig` through `options=...`. Its fields set the defaults.
The function writes to the module-level singleton `LOGGING_CONFIG`, from which the hooks read whenever the corresponding `with_logger` argument was not supplied.

**Environment variables override the function arguments**, not the other way round:

| Variable | Field |
|---|---|
| `HTTP_CLIENT_LOG_LEVEL` | `log_level` (integer) |
| `HTTP_CLIENT_USE_LINE_BREAKS` | `use_line_breaks` (`true`/`y`/`yes`/`on`) |
| `HTTP_CLIENT_JSON_INDENT` | `json_indent` |
| `HTTP_CLIENT_OCTET_STREAM_LOG_MAXLENGTH` | `octet_stream_log_maxlength` |
| `HTTP_CLIENT_PLAIN_TEXT_LOG_MAXLENGTH` | `plain_text_log_maxlength` |
| `HTTP_CLIENT_JSON_LOG_MAXLENGTH` | `json_log_maxlength` |

The length limits (`*_maxlength`) trim the middle of the string, keeping the head and tail and inserting `...`. They can only be set globally; `with_logger` does not accept them.

## Utilities

`http_client.utils.sanitizer.sanitize(value, sensitive_keys)` — masks a dict or list using the same glom paths. Returns a deep copy and leaves the original untouched.

`http_client.utils.traceparent.generate()` — a traceparent string.

`http_client.utils.logutils.create_request_log` / `create_response_log` — build the same log strings manually.

`http_client.utils.logutils` also exports the building blocks those two are made of, so a logger built
on a different backend renders bodies exactly the same way: `to_json`, `trim`, `decode`, `is_streamed`,
`is_buffered`, `parse_error`. These helpers are part of the public API.

## Inherited client attributes

| Attribute | Where it is set | Purpose |
|---|---|---|
| `DEFAULT_URL_SUFFIX` | overridden in the subclass | path prefix injected by the `endpoint()` method |
| `DEFAULT_TIMEOUT` | overridden in the subclass | default timeout, `httpx.Timeout(60)` |
| `base_url` | from the constructor | proxies `self.client.base_url` |
| `client` | created in `__init__` | the underlying `httpx.Client` / `httpx.AsyncClient` |

Lifecycle mirrors `httpx` exactly: the connection pool is built in the constructor, `__enter__` / `__aenter__` open it, and `__exit__` / `__aexit__` close it. `HttpClient.close()` and `AsyncHttpClient.aclose()` do the same for a client not used as a context manager — the naming follows `httpx`, so the async client has `aclose()` only. A closed client cannot be reopened; doing so raises `RuntimeError`.

`endpoint(path)` joins `url_suffix` with `path`. Leading slashes on `path` and a missing trailing slash on the suffix are both normalized, so `"/u-api/orders/v1"` and `"/u-api/orders/v1/"` behave identically. It accepts relative paths only: an absolute URL or a `..` segment raises `ValueError`.
