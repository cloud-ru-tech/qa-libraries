# Option catalog and configuration

All options live in `grpc_client.options`. Each one returns a `ClientOption` — a callable applied to the client inside `__init__`, before the channel is created.

## Channel and transport

### `with_timeout(timeout: float | None) -> ClientOption`

Default deadline for every call, in seconds. `None` means no deadline.

The default is `BaseGRPCClient.DEFAULT_TIMEOUT_SEC` — **60 seconds**. Bare grpcio has no default deadline; this library imposes one so a hung call cannot hold a test run until the CI job times out. Override it per client with this option, per subclass by redefining `DEFAULT_TIMEOUT_SEC`, or per call with `CallOptions(timeout=...)`.

### `with_insecure_channel() -> ClientOption`

Plaintext channel. Everything on the wire, access tokens included, is unprotected — local debugging and test stands only.

The channel is encrypted by default: without this option the client builds a secure channel with `grpc.ssl_channel_credentials()`.

### `with_ssl_credentials(credentials: grpc.ChannelCredentials) -> ClientOption`

Custom TLS channel credentials, e.g. carrying a corporate root certificate. Also forces `secure = True`, so combining it with `with_insecure_channel()` makes the outcome depend on the order — the later option wins.

### `with_root_certificates(root_certificates: bytes) -> ClientOption`

Shorthand for `with_ssl_credentials(grpc.ssl_channel_credentials(root_certificates=...))`. Takes the contents of a PEM file, not a path.

### `with_channel_options(options: ChannelOptions) -> ClientOption`

Low-level grpcio channel options. Replaces the whole tuple rather than appending, so pass every option in one call.

This is where grpcio's built-in retries are configured — do not hand-roll a retry loop:

```python
import json

options.with_channel_options(
    [
        ("grpc.enable_retries", 1),
        (
            "grpc.service_config",
            json.dumps(
                {
                    "methodConfig": [
                        {
                            "name": [{"service": "example.Orders"}],
                            "retryPolicy": {
                                "maxAttempts": 4,
                                "initialBackoff": "0.1s",
                                "maxBackoff": "1s",
                                "backoffMultiplier": 2,
                                "retryableStatusCodes": ["UNAVAILABLE"],
                            },
                        }
                    ],
                }
            ),
        ),
    ]
)
```

### `with_compression(compression: grpc.Compression) -> ClientOption`

Message compression. Applied both when creating the channel and as the default for each call, so a per-call `CallOptions(compression=...)` overrides it.

## Metadata

### `with_default_metadata(metadata: MetadataType) -> ClientOption`

Metadata appended to every request. Accumulates: applying the option twice keeps both sets, in order of application.

These pairs go in front of any per-call metadata. Interceptor-added metadata is appended after both, since interceptors run on the channel.

### `with_autogenerated_request_id(key: str | None = None) -> ClientOption`

Adds a UUID4 under `x-request-id`. The key can be changed by argument or by the `GRPC_CLIENT_REQUEST_ID_KEY` environment variable.

If the request already carries that key, the existing value is kept.

### `with_autogenerated_traceparent(key: str | None = None) -> ClientOption`

Adds a W3C Trace Context value `00-<32 hex>-<16 hex>-01` under `traceparent`. Key overridable by argument or by `GRPC_CLIENT_TRACEPARENT_KEY`.

This is standalone generation, not an OpenTelemetry integration: no context is picked up from a current span. An existing value is kept.

## Authentication

### `with_auth(auth: ClientAuth | AsyncClientAuth, *, retry_on_unauthenticated: bool = True) -> ClientOption`

Injects `authorization: Bearer <token>` into every request.

The implementation is picked by client type, and the two protocols are told apart by whether `token()` is a coroutine function — they declare identical method names, so `isinstance` cannot distinguish them (which is why neither protocol is `runtime_checkable`). A mismatch raises `TypeError` at client construction:

- sync client + async implementation → `Синхронному клиенту нужна синхронная реализация ClientAuth`
- async client + sync implementation → `Асинхронному клиенту нужна асинхронная реализация AsyncClientAuth`

With `retry_on_unauthenticated=True` (default) an `UNAUTHENTICATED` reply triggers `refresh(rejected_token)` and one repeat — **unary calls only**.

The key and scheme are fixed at `authorization` / `Bearer` in the option. For other values instantiate `AuthInterceptor(auth, key=..., scheme=...)` directly and pass it via `with_interceptor`.

## Interceptors

### `with_interceptor(*interceptors: object) -> ClientOption`

Adds grpcio interceptors, sync or async depending on the client. They are applied in the order added.

For an async client each interceptor goes through `split_async_interceptor()` first — see `pitfalls.md`.

## Logging

### `with_logger(logger, *, sanitize_keys=None, log_level=None, err_log_level=None, json_indent=None, use_line_breaks=None, payload_maxlength=None, use_default_sanitize_keys=True) -> ClientOption`

| Parameter | Type | Meaning |
|---|---|---|
| `logger` | `logging.Logger` | where records are written |
| `sanitize_keys` | `Sequence[str] \| None` | metadata key names and message-body paths whose values become `****` |
| `log_level` | `int \| None` | level for successful calls; defaults to the global config |
| `err_log_level` | `int \| None` | level for failed calls; defaults to the global config |
| `json_indent` | `int \| None` | indent for the JSON parts of a record |
| `use_line_breaks` | `bool \| None` | newlines between record parts instead of spaces |
| `payload_maxlength` | `int \| None` | maximum message-body length in a record |
| `use_default_sanitize_keys` | `bool` | also mask the built-in secret list (default `True`) |

Record shapes:

```
GRPC request sent: id=<uuid> Method: /package.Service/Method Payload: {...} Metadata: {...}
GRPC response received: id=<uuid> Status: 0 (OK) Method: /package.Service/Method Payload: {...} Metadata: {...}
GRPC stream finished: id=<uuid> Status: 0 (OK) Method: /package.Service/Method Messages: 12 Metadata: {...}
GRPC error occurred: id=<uuid> Status: 5 (NOT_FOUND) Method: /package.Service/Method Error: <details> Metadata: {...}
```

`id` links a request to its response. It is generated per call by the interceptor and has nothing to do with server-side tracing — for that use `with_autogenerated_traceparent`.

Notes on what lands in a record:

- a client request stream logs `Payload: <поток сообщений>` — the iterator is not consumed for the log;
- a server response stream logs no payload at all, only the final status and message count;
- a body that cannot be rendered becomes `<не удалось подготовить тело сообщения>`; a body over `payload_maxlength` is cut with `... <обрезано>`;
- a repeated metadata key is rendered as a list of its values, so the record matches what was actually sent;
- when the logger is disabled for both levels the interceptor short-circuits: no id is generated and streams are not wrapped for counting.

### `with_log_sink(sink, log_level=None, err_log_level=None) -> ClientOption`

The extension point behind `with_logger`. The interceptor decides **what happened** — it builds a record and picks the level — and the sink decides **where and in what shape** it lands.

| Parameter | Type | Meaning |
|---|---|---|
| `sink` | `LogSink` | receiver of the records |
| `log_level` | `int \| None` | level for successful calls; defaults to the global config |
| `err_log_level` | `int \| None` | level for failed calls; defaults to the global config |

`LogSink` is a `Protocol` — three methods, no base class required, though subclassing it explicitly buys you mypy signature checks and an error on a forgotten method:

```python
class LogSink(Protocol):
    def is_enabled_for(self, level: int) -> bool: ...
    def write_request(self, level: int, record: RequestRecord) -> None: ...
    def write_response(self, level: int, record: ResponseRecord) -> None: ...
```

`RequestRecord` is `(trace_id, method, message, metadata)`; `message` is `None` when the request body was a stream.

`ResponseRecord` is `(trace_id, method, status_code, message, details, metadata, messages_count)` and covers all three outcomes with one shape:

| Outcome | `status_code` | `message` | `details` | `messages_count` |
|---|---|---|---|---|
| unary success | `OK` | the response | `""` | `None` |
| stream finished | `OK` | `None` | `""` | count |
| any failure | the error code | `None` | service error text | count for streams, `None` for unary |

Do not re-derive the outcome from that combination — the record answers it: `record.succeeded` (status is `OK`) and `record.is_stream` (`messages_count` is set). `TextLogSink` picks its three text shapes off exactly those two.

`is_enabled_for` is asked **before** the record is built — assembling a body costs `MessageToDict` plus masking plus `json.dumps`, the question does not. When both levels answer `False` the interceptor short-circuits entirely: no `trace_id`, no stream wrapper.

Three constraints on an implementation:

- **it is called from several threads** — the final stream log comes from a grpcio channel thread, the async one from an event-loop task;
- **it is called on the hot path** — the request record is written before the call is sent, so slow work inside the sink delays the call itself;
- **it must not count on being able to fail** — an exception is swallowed and reported to the `grpc_client.interceptors.logging` logger, the call goes through, and that one record is lost.

Formatting is the sink's own business, so `with_log_sink` has no `sanitize_keys` / `json_indent` / `payload_maxlength` parameters. `grpc_client.LogFormat.from_config(...)` builds the rules with the `configure_logging` values filled in for anything left `None`, and `grpc_client.utils.logutils` exposes the helpers that turn a record into text.

`TextLogSink(logger, log_format=None)` is the built-in implementation; `with_logger(...)` is shorthand for constructing it. `grpc_client.resolve_log_levels(log_level, err_log_level)` returns the pair of levels the interceptor will use — needed when a sink must reject an unusable level before the client is built.

### Masking

Built-in secret list (`grpc_client.utils.sanitizer.DEFAULT_SANITIZE_KEYS`): `authorization`, `proxy-authorization`, `cookie`, `set-cookie`, `x-api-key`, `api-key`, `api_key`, `access_token`, `refresh_token`, `password`, `secret`, `token`. Anything in `sanitize_keys` is added on top; turn the defaults off only with `use_default_sanitize_keys=False`.

Metadata and message bodies are masked by different rules:

| Target | Rule |
|---|---|
| metadata | whole key name, case-insensitive; no path parsing, because gRPC metadata is flat and its keys may contain dots |
| body, key without separators (`password`) | that field name at any nesting depth, list elements included |
| body, key with `.` `*` `[` `(` (`user.password`, `items.*.token`) | applied as a glom path |

Name matching is style-insensitive, resolved by normalizing to snake_case: `access_token` also hides `accessToken`, `APIKey`, `token2FA`. Word boundaries are respected, so `secret` does not match `sec_ret` and `token` does not match `tokenizer`. A compound name ending in a secret does match: `user_password` and `client_secret` are masked by `password` and `secret`.

Body traversal is depth-limited at 64 levels; anything deeper is replaced with `<превышена глубина вложенности>` rather than passed through, since it may still hold a secret.

Masking covers the records this library writes. It does not cover grpcio's own exception text.

### `configure_logging(...)` — global defaults

```python
from grpc_client import configure_logging

configure_logging(
    log_level=logging.INFO,
    err_log_level=logging.ERROR,
    json_indent=None,
    use_line_breaks=False,
    payload_log_maxlength=4096,
)
```

Writes to the module-level singleton `grpc_client.config.LOGGING_CONFIG`, which the interceptors read whenever the matching `with_logger` argument was omitted.

**Environment variables override the function arguments**, not the other way round:

| Variable | Field |
|---|---|
| `GRPC_CLIENT_LOG_LEVEL` | `log_level` (integer) |
| `GRPC_CLIENT_ERR_LOG_LEVEL` | `err_log_level` (integer) |
| `GRPC_CLIENT_JSON_INDENT` | `json_indent` |
| `GRPC_CLIENT_USE_LINE_BREAKS` | `use_line_breaks` (`true`/`y`/`yes`/`on`/`1`) |
| `GRPC_CLIENT_PAYLOAD_LOG_MAXLENGTH` | `payload_log_maxlength` |

Two more variables are read by the observability interceptors, not by `configure_logging`: `GRPC_CLIENT_REQUEST_ID_KEY` and `GRPC_CLIENT_TRACEPARENT_KEY`.

## Utilities

`grpc_client.utils.sanitizer`
- `sanitize(value, sensitive_keys)` — masks a dict or list by the rules above; returns a copy, leaves the original untouched.
- `sanitize_metadata(metadata, sensitive_keys)` — the same for metadata pairs.
- `DEFAULT_SANITIZE_KEYS`, `MASK`, `MAX_DEPTH`.

`grpc_client.utils.traceparent`
- `generate(flags=FLAGS_SAMPLED)` — a W3C Trace Context string.

`grpc_client.utils.logutils`
- `request_log`, `response_log`, `stream_response_log`, `error_log` — build the same strings by hand, e.g. from a logger on a different backend.
- `LogFormat` — the formatting rules those four take.

## Client attributes

| Attribute | Where it is set | Purpose |
|---|---|---|
| `DEFAULT_TIMEOUT_SEC` | class attribute, overridable in a subclass | default deadline, `60.0` |
| `timeout` | `with_timeout`, read per call | current default deadline |
| `secure` | `with_insecure_channel` / `with_ssl_credentials` | whether the channel is encrypted |
| `ssl_credentials` | `with_ssl_credentials` | TLS channel credentials |
| `compression` | `with_compression` | default compression |
| `channel_options` | `with_channel_options` | grpcio channel options |
| `default_metadata` | `with_default_metadata` | metadata added to every request |
| `channel` | built in `__init__` | the underlying `grpc.Channel` / `grpc.aio.Channel` |
| `stub` | built in `__init__` | the generated stub over that channel |

`timeout`, `default_metadata` and `compression` are read when a call is assembled, so changing them after construction does take effect — but do it through options anyway, since the channel-level fields around them do not behave that way.
