# Structured logging for http_client

The library exports exactly one name: `with_structlogger`. It is a `ClientOption` that replaces
`http_client.options.with_logger`. Instead of one text line per call, every attribute — method, URL,
headers, body, status — becomes its own [structlog](https://www.structlog.org) field, so logs can be
filtered and searched by field rather than by substring.

Everything else — building the client, endpoints, timeouts, auth, decorators — is plain `http_client`.
This library adds no client of its own and no way to log outside of the option.

## Hard rules

1. Install **one** logging option. `with_structlogger` and `options.with_logger` each append their own
   hooks; passing both logs every request twice.
2. Pass it as a constructor option, exactly like the built-in ones. There is no post-construction setup.
3. Requires `http-client` **2.1 or newer**. Earlier versions lack the public log helpers this library
   imports, and the async client will fail on import.
4. `sanitize_keys` holds **exact glom paths**; the default secret list works **by field name at any
   depth**. They are two different mechanisms — see `references/fields.md` before adding a path.
5. Write header names lowercase (`"authorization"`) — httpx lowercases them before the hook sees them.
6. Do not turn off `use_default_sanitize_keys` to "clean up" the log. It unmasks passwords and tokens.

Before debugging odd output, read `references/pitfalls.md` — it covers the non-obvious behaviour.

## Usage

```python
import httpx
import structlog
from http_client import HttpClient
from http_client_structlog import with_structlogger


class OrdersClient(HttpClient):
    def get_order(self, order_id: str) -> httpx.Response:
        request = self.client.build_request("GET", f"/orders/{order_id}")
        return self.send(request)


with OrdersClient("https://api.example.com", with_structlogger(structlog.get_logger("orders"))) as client:
    client.get_order("42")
```

Combines with any other option:

```python
from http_client import options
from httpx import BasicAuth

client = OrdersClient(
    "https://api.example.com",
    options.with_auth(BasicAuth("admin", "PazzW0rD")),
    options.with_timeout(30),
    with_structlogger(logger, json_indent=2),
)
```

## Async client

Same option, same arguments. The right response hook — sync or async — is picked from the client type
inside the option, so nothing extra is configured:

```python
from http_client import AsyncHttpClient


class AsyncOrdersClient(AsyncHttpClient):
    async def get_order(self, order_id: str) -> httpx.Response:
        request = self.client.build_request("GET", f"/orders/{order_id}")
        return await self.send(request)


async with AsyncOrdersClient("https://api.example.com", with_structlogger(logger)) as client:
    await client.get_order("42")
```

## What lands in the log

Two events per call, linked by `trace_id`:

| Field | Event | Value |
|---|---|---|
| `event` | both | `http request sent` / `http response received` |
| `method` | request | uppercase HTTP method |
| `url` | request | `scheme://host/path`, without the query string |
| `query_params` | request | JSON string; omitted when the URL has no query |
| `headers` | both | JSON string |
| `body` | both | rendered by `Content-Type`; omitted when there is no body |
| `status_code` | response | `int` |
| `trace_id` | both | UUID4 generated per request |

`status_code` is the only non-string field: composite values are serialized to JSON strings, not passed
as nested dicts. The full catalog — body rendering per content type, truncation, streaming placeholders,
parse errors — is in `references/fields.md`.

`trace_id` is an internal request↔response link stored in `request.extensions["trace_id"]`. It has
nothing to do with server-side tracing; for that use `options.with_autogenerated_traceparent()`.

## Masking

Fields whose **name** is a common secret — `authorization`, `cookie`, `token`, `password`, `api_key`
and the rest of `http_client.event_hooks.DEFAULT_SANITIZE_KEYS` — are replaced with `****` by default,
**at any depth**, including inside nested objects and array elements.

Project-specific fields go into `sanitize_keys` as [glom](https://glom.readthedocs.io/en/latest/) paths.
They apply to headers, query parameters, and the JSON body, and they **add to** the default list rather
than replacing it:

```python
with_structlogger(logger, sanitize_keys=["user.internal_id", "items.*.card_number"])
```

| Path | What it masks |
|---|---|
| `x-tenant-key` | a header (lowercase name) |
| `user.internal_id` | a nested body field |
| `items.*.card_number` | a field in every array element |
| `*.owner.email` | a field when the body itself is an array |

A path that matches nothing is skipped silently. Masking never touches the response object the caller
gets back — only the copy that goes into the log.

## Parameters

| Parameter | Type | Meaning |
|---|---|---|
| `logger` | `structlog.stdlib.BoundLogger` | where to write |
| `sanitize_keys` | `Sequence[str] \| None` | glom paths replaced with `****` |
| `json_indent` | `int \| None` | indent used when serializing JSON fields |
| `log_level` | `int \| None` | record level, defaults to `INFO` |
| `use_default_sanitize_keys` | `bool` | mask common secret names at any depth, default `True` |

`log_level` and `json_indent` fall back to the global `http_client` settings when omitted — set them
once for the whole project with `http_client.configure_logging(...)` or the `HTTP_CLIENT_*` environment
variables. An argument passed to `with_structlogger` wins over the global value.
